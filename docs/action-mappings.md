# Custom gesture action mappings

The **Actions** page maps labels from the currently loaded custom classifier to local keyboard shortcuts. Mappings are stored in `%LOCALAPPDATA%\\GestureManager\\settings\\actions.json`, separate from feature datasets and model files. The JSON format is `gesture-manager-actions`, version 1. It contains an array of records with a gesture ID/name, the allowlisted action type `keyboard_shortcut`, normalized shortcut, and an independent enabled flag. Writes use a temporary file and atomic replacement. Unknown action types, unknown keys, malformed shortcuts, and unsupported versions are rejected. Profile content is never interpreted as code or a shell command.

Supported shortcuts contain one allowlisted keyboard key, optionally with `Ctrl`, `Alt`, `Shift`, or `Win`. You can map a single letter or key (such as `A`, `Space`, or `F5`) as well as combinations such as `Ctrl+C`, `Ctrl+V`, `Ctrl+Z`, `Alt+Tab`, and `Win+D`. The allowlist includes letters, digits, F1–F12, navigation/edit keys, common punctuation, and standard lock/system keys; unknown device-specific keys and mouse buttons are not supported. The recorder listens globally only after **Start capture** is pressed and stops after it captures one valid key or chord. On Windows the captured key or chord is suppressed during recording to avoid typing or performing it in another app. A mapping is disabled by default. Recognition may continue while its action is disabled.

Each process starts in dry-run mode. The active profile saves the user's Dry-run or Real-input preference. When Real input is saved, the app asks for explicit confirmation at startup and before a service restart after its consent was cleared; declining preserves the saved choice while this session remains in dry-run. An eligible recognition event in dry-run displays the intended shortcut but never sends it. The pynput backend imports lazily after confirmation. It presses a validated chord and releases every pressed key in reverse order, including when a key operation fails. A per-gesture cooldown and an additional global rate limit prevent rapid repeat dispatch. The tray menu and Actions page provide a global emergency stop; rearming requires confirmation and returns dispatch to dry-run mode.

Keyboard shortcuts are sent to the application that has focus at dispatch time. On Windows, while the explicit recorder is active, pynput's low-level hook suppresses supported modifier keys and the captured key so single-key mappings and system shortcuts such as Alt+Tab and Win+D are recorded without being performed. Capture ends after one valid key or chord; canceling also stops the listener. The application does not request administrator privileges. If pynput is unavailable, dry-run still works and the app reports that real input needs the project dependency installed. On other platforms, captured keys may reach the focused application, and system-level chords may execute during capture.

## Automated test boundary

`tests/test_actions.py` uses a mock backend. It covers mapping persistence, schema/action allowlists, shortcut validation, dry run, disabled actions, cooldown, emergency stop, and key-release behavior. It does not send real input.
